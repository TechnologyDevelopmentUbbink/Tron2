# Writing Style

Write for engineers who may be unfamiliar with the current setup. Keep information traceable, concise, and safe to apply.

## Style requirements

- Write in English using clear technical language.
- Keep procedures short and focused on one outcome.
- Use numbered steps for actions that must be performed in sequence.
- Use tables for specifications and compact comparisons.
- Put commands in fenced code blocks and identify the shell where useful.
- Place warnings before steps that could be dangerous or cause damage.
- Avoid unsupported claims and mark uncertain content as **Unverified**.
- State firmware, SDK, ROS package, and hardware versions where relevant.
- Link to related pages instead of duplicating procedures.

## Structure

Use one `#` heading for the page title, `##` for major sections, and `###` only when needed. Begin with the page's purpose, list prerequisites before the procedure, and finish with verification, troubleshooting, sources, or related pages as appropriate.

## Commands

Keep commands copyable and explain placeholders outside the block:

```bash
# Example placeholder only; replace with a verified project command.
command --option VALUE
```

Never publish invented commands or procedures.
